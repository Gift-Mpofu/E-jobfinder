E-JOB FINDER: FULL APPLICATION BRIEF & HANDOFF DOCUMENT

=========================================
1. THE END GOAL (THE PIVOT)
=========================================
The initial prototype was an "E-Job Scanner"—a manual utility where a user uploaded their CV, pasted a single Job Description, and an AI would compare the two, granting a score and missing keywords.
THE END GOAL is to pivot into an active "E-Job Finder," an automated recruitment platform where:
- A user uploads their CV once.
- The AI extracts their structural skills, seniority, and preferences into a standardized database format.
- The app automatically surfaces, ranks, and alerts the user to active, live job openings (`live_jobs`) that have a high "Match Score" with their profile.

=========================================
2. THE TECHNOLOGY STACK
=========================================
- Frontend: Next.js 15 (App Router, Turbopack, React 19)
- Styling: Tailwind CSS, `shadcn/ui` (Radix UI components)
- Backend & Auth: Supabase
- Edge Functions: Deno / TypeScript via Supabase Functions
- AI Engine: Google Genkit (`@genkit-ai/google-genai`)

=========================================
4. DATABASE SCHEMA SUMMARY (SUPABASE POSTGRESQL)
=========================================
TABLE: profiles
- id, email, target_role, scans_used, photo_url, last_active, role, status, location, experience_level, career_goals, skills (text[]), last_scan_reset

TABLE: live_jobs (The New Feature Table)
- id, external_id (UNIQUE), title, company, location, description_text, url, skills_required[], seniority, salary_max/min, posted_at, status ('open'), source, creation_date

TABLE: user_job_actions
- id, user_id (ref: profiles), job_id (ref: live_jobs), action_type ('saved'), created_at

TABLE: cvs / job_descriptions / match_results
- Used primarily for the legacy 1-to-1 CV scanner.

We need to transition this to either a backend Supabase Postgres RPC (vector similarity or extensive JSONB array logic) so we can scale beyond fetching thousands of rows to the client browser.
